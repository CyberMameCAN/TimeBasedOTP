# TOTP with Python

Pythonで **TOTP（Time-based One-Time Password：時間ベースのワンタイムパスワード）** の生成と検証を試す学習用プロジェクトです。

共有秘密鍵を生成し、QRコードを使ってスマートフォンの認証アプリに登録します。その後、認証アプリに表示されたコードをPython側で検証できます。

> このプロジェクトは仕組みを理解するためのサンプルです。そのまま本番環境の認証機能として使用することは想定していません。

## TOTPの仕組み

認証する側（このPythonプログラム）と認証アプリが、同じ**共有秘密鍵**と**現在時刻**を使ってコードを計算します。コードそのものを両者の間で送受信しているわけではありません。

このプロジェクトではPyOTPのデフォルト設定を使い、**6桁のコードを30秒単位**で生成します。

1. Pythonで共有秘密鍵を生成する。
2. 共有秘密鍵などを含む登録用URIをQRコードにする。
3. 認証アプリでQRコードを読み取り、共有秘密鍵を登録する。
4. 認証アプリに表示されたコードをPython側に入力する。
5. Python側で計算したコードと照合し、認証の成否を表示する。

**共有秘密鍵は、ワンタイムパスワードとは異なり、登録後も継続して使う重要な情報です。** 秘密鍵が漏れると、第三者も有効なコードを生成できるようになります。

## 使用環境・ライブラリ

- Python 3.14以上（`pyproject.toml` の指定）
- [uv](https://docs.astral.sh/uv/)：Python環境・依存関係の管理
- PyOTP：共有秘密鍵の生成、TOTPの生成・検証
- qrcode / Pillow：QRコード画像の生成
- Google Authenticatorなど、TOTPに対応した認証アプリ

秘密鍵ファイルの権限設定には `os.fchmod()` を使用しているため、現在の実装はLinuxなどのUnix系環境を想定しています。

## 環境構築

uvをインストールしたうえで、プロジェクトのルートディレクトリ（このREADMEがある場所）で実行します。

```bash
uv sync
```

以降のコマンドも、プロジェクトのルートディレクトリで実行してください。

## 使い方

### 1. 共有秘密鍵を作成する

```bash
uv run python -m src.totp.create_secret_key
```

Base32形式の共有秘密鍵が生成され、`src/totp/maruhi/secret.txt` に保存されます。保存先フォルダがなければ自動作成します。

ファイルの権限は **`600`（所有者のみ読み書き可能、実行不可）** に設定します。これはアクセス権限の制限であり、ファイルの暗号化ではありません。

> **再実行すると、既存の秘密鍵は新しい秘密鍵で上書きされます。** すでに認証アプリに登録している場合は、次の手順で新しいQRコードを生成し、アプリ側も登録し直してください。通常の認証のたびに秘密鍵を作り直す必要はありません。

### 2. QRコードを生成し、認証アプリに登録する

```bash
uv run python -m src.totp.main
```

`main.py` は秘密鍵ファイルを読み込み、実行時のカレントディレクトリに `otp_qr.png` を生成します。上記の手順ではプロジェクトのルートに保存されます。

プログラムが認証コードの入力待ちになったら、画像を開き、スマートフォンの認証アプリで読み取ってください。スマートフォン自身で画像を表示する場合は、別の画面に表示するなど、アプリで読み取れる方法を使います。

登録名は現在、次の値を使用しています。変更する場合は `src/totp/main.py` の `totp.provisioning_uri()` を編集してください。

- アカウント名：`user@example.com`
- 発行者名：`MyPythonApp`

> QRコードにも共有秘密鍵が含まれます。`secret.txt` と同様に、第三者への共有や公開は避けてください。

### 3. 認証コードを入力する

認証アプリに表示された6桁のコードを、ターミナルに入力します。

```text
認証コードを入力してください: 123456
認証成功！
```

上の数値は入力形式の例です。実際には、その時点でアプリに表示されているコードを入力してください。先頭が `0` の場合も、省略せず6桁すべて入力します。

一致しない場合は `認証失敗...` と表示されます。現在の実装では1回検証すると終了します。再度試す場合は `main.py` を実行し直してください。同じ秘密鍵を使っていれば、アプリへの再登録は不要です。

## 認証に失敗するときの確認事項

- **秘密鍵ファイルがない**：先に `create_secret_key.py` を実行してください。ファイルがない場合は `FileNotFoundError` になります。
- **登録後に秘密鍵を再生成した**：新しいQRコードで認証アプリに登録し直してください。
- **コードの有効期間が切れた**：アプリで次のコードに切り替わってから、もう一度試してください。
- **PCとスマートフォンの時計がずれている**：双方の日時の自動設定・時刻同期を確認してください。TOTPではタイムゾーンの表示よりも、実際の時刻が正しいことが重要です。

## セキュリティ上の注意・未対応事項

### 秘密鍵の保存と表示

- 共有秘密鍵は暗号化せず、平文で保存しています。権限 `600` でも、所有者権限で動くプログラムや管理者からの読み取りまでは防げません。
- 学習用として、`create_secret_key.py` は秘密鍵を、`main.py` は現在のTOTPコードをターミナルに表示します。本番用途では、このような表示やログ出力を避けてください。
- **`secret.txt` と `otp_qr.png` はGitにコミットしたり、スクリーンショットなどで公開したりしないでください。** `.gitignore` で除外することを推奨します。すでに公開した場合は、除外設定だけでなく、秘密鍵の再生成と認証アプリの再登録が必要です。
- 本番環境では、アクセス制御に加えて、秘密鍵の暗号化や暗号鍵の管理方法を検討してください。TOTPの検証には元の秘密鍵が必要なため、パスワードのような一方向ハッシュへの置き換えはできません。

### 時刻のずれへの対応（Time drift）

現在は `totp.verify(input_code)` を使用し、**検証時点の30秒区間のコードのみ**を受け付けます。入力中に区間が切り替わった場合や、端末間の時計がずれている場合は、認証に失敗することがあります。

PyOTPでは、たとえば `totp.verify(input_code, valid_window=1)` とすると、現在の区間に加えて前後1区間のコードも許容できます。ただし、受け付ける範囲を広げるほど有効なコードの範囲も広がるため、必ず設定すべきものではありません。まず時計を同期し、用途に応じて許容範囲を検討します。このプロジェクトでは許容範囲の拡張は行っていません。

### 本番の認証機能として不足しているもの

- 同じ時間区間内で、一度使用したコードが再利用されることの防止
- 認証試行回数の制限（レート制限）
- ユーザーごとの秘密鍵の管理、登録・再登録の手続き
- 認証アプリを紛失した場合の復旧手段
- パスワード認証などと組み合わせたログイン処理（このサンプル単体では多要素認証にはなりません）
